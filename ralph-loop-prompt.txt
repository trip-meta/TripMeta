## 每轮迭代执行流程

### 1. 状态检查
执行以下命令检查当前状态：
cd /d/project/TripMeta/TripMeta
git log --oneline -5
grep -A 10 "Phase 1" docs/FUTURE_ROADMAP.md

确定：
- 上一轮的完成情况
- 当前 Phase 中第一个未完成的 [ ] 项
- 代码质量和性能瓶颈

### 2. 实施优化
针对选中的任务：
- 创建/修改 C# 脚本于 Assets/Scripts/ 对应目录
- 遵循现有依赖注入架构（ServiceInstaller 注册服务）
- 编写单元测试（Assets/Scripts/Tests/）
- 添加性能基准测试

### 3. 验证成果
- 运行所有单元测试，确保通过
- 量化性能改进（如：延迟从 2000ms 降至 500ms）
- 检查无回归问题

### 4. 提交代码
git add .
git commit -m "perf: 具体优化描述 - 性能提升数据"
git push origin main

### 5. 继续判断
检查当前 Phase 是否还有未完成的 [ ] 项：
- 如果还有：继续下一轮迭代（不要输出完成标记）
- 如果当前 Phase 完成：进入下一个 Phase
- 如果所有 Phase 完成：输出完成标记

## 重要规则

1. 一轮一个任务 - 每轮只专注于一个具体优化项
2. 量化成果 - 必须提供性能改进的前后对比数据
3. 持续迭代 - 不要每轮都输出完成标记，让循环继续
4. 质量保证 - 每个优化都必须有单元测试覆盖
5. 向后兼容 - 不破坏现有功能
